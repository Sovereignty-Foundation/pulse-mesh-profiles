# `rings/` — Tier 3: domain surfaces

Domain surfaces composed on the standard, each the same four crates: `<name>-core` (shared types, no state, no I/O), `<name>-functions` (stateless transformations), `<name>-stages` (stateful hot-path primitives) and `<name>-hub` (the composition surface, which re-exports the inner layers and declares them through `register_stages!`, the macro the standard holds under `core/mesh-stage-registry`). Downstream code depends on a ring's hub crate, never on its inner layers, and a `core` or `functions` crate may be an empty placeholder so the shape stays uniform. Three rings are here: `enterprise_ring/` (the TLS transport stage: TLS 1.3 over TCP, with DTLS and the QUIC tunnel deferred), `hft_ring/` (wait strategies, the MultiLane ring, the SPMC ring, NUMA placement) and `robotics_ring/` (the large-payload pool, the io_uring transport and the autoscale stage). The fourth, the general-purpose dev ring, is in the daemon's repository beside the daemon it serves. The book describes the shape in [Rings: domain surfaces](../book/src/architecture/rings/overview.md) and each ring on its own page; [Add a stage to a ring](https://pulse-mesh.net/docs/daemon/guides/add-a-stage.html) is the guide for changing one.
